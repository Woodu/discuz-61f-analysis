## TDD 开发流程

### Red-Green-Refactor 循环

```
1. RED:   编写失败的测试
2. GREEN: 编写最小实现使测试通过
3. REFACTOR: 重构优化代码
```

## 测试执行计划

### 开发阶段
- 每个功能开发前先编写测试
- 运行测试确保失败 (RED)
- 实现功能直到测试通过 (GREEN)
- 重构代码保持测试通过

### 持续集成

| 事件 | 测试范围 | 执行时间 |
|------|----------|----------|
| 每个 PR | 单元 + 组件 + 关键 E2E | < 15 分钟 |
| 合并到 main | 全量测试 | < 30 分钟 |
| 发布前 | 全量 + 性能 + 安全 | < 45 分钟 |

## 测试最佳实践

### 单元测试
- 测试单一行为
- Mock 外部依赖
- 使用描述性测试名称

### 组件测试
- 测试用户行为，非实现细节
- 使用 userEvent 而非 fireEvent
- 测试可访问性

### E2E 测试
- 测试关键用户流程
- 使用稳定的选择器 (data-testid)
- 等待网络请求完成
